# LogNoJutsu — Improvement Research (post-v1.4)

*Compiled 2026-09-20 after a full read of the codebase (~8.3k LOC Go, 59 techniques, 12 campaigns).*

This document catalogs improvement opportunities found by reading the whole tool, ranked by
value/risk. Items marked **[implemented]** were done in this pass; the rest are recommendations
for a future milestone.

## Method

Read every production file: `cmd/lognojutsu`, and `internal/{engine,executor,native,playbooks,
preparation,reporter,server,simlog,userstore,verifier}`, plus the embedded YAML technique/campaign
corpus and the SPA (`internal/server/static/index.html`). Baseline: `go build ./...` clean,
`go test ./...` all green.

## Tier 1 — High value, addressed this pass

### 1. Credentials leak onto the PowerShell command line **[implemented]**
**Where:** `userstore.go` (`encryptDPAPI`, `decryptDPAPI`, `TestCredentials`) and
`executor.go` (`runCommandAs`).

**Problem:** Every one of these interpolates the *plaintext* password (or DPAPI blob) directly
into the `powershell.exe -Command "<script>"` argument. A process command line is world-readable
to any process on the host and — critically — is captured by **Event 4688 (process creation with
command line)** and **PowerShell ScriptBlock logging (4104)**, both of which this very tool turns
on in the Preparation step. So the tool exfiltrates the simulation credentials into the exact logs
it tells the SIEM to collect. The hand-rolled backtick/quote/`$` escaping is also fragile
(a password containing an unescaped metacharacter breaks the script or changes its meaning).

**Fix:** Pass secrets via an environment variable (`$env:LNJ_*`) with the script delivered on
stdin (`-Command -`). Env vars are not on the command line and are only visible to the same-user
process tree. This also *removes* the fragile escaping entirely. Verified on-box that
`$env:VAR` + stdin transport works.

### 2. `EventSpec.Contains` is parsed but never enforced **[implemented]**
**Where:** `playbooks/types.go` declares `Contains`; four techniques set it
(`T1070_001`, `T1490`, `UEBA_privilege_escalation_chain`, and one in a comment). `verifier.Verify`
ignores it — it only counts events by `(channel, id)`.

**Problem:** A technique that clears logs (`contains: wevtutil`) is "verified" by *any* 4688 in the
window, not by the one whose command line contains `wevtutil`. This makes verification report false
passes and undersells the tool's core value (precise pass/fail).

**Fix:** Thread `contains` through `QueryFn`; `DefaultQueryFn` adds a
`-and ($_.Message -like '*contains*')` filter when set. Backward compatible (empty `contains`
behaves exactly as before).

### 3. Password-protected UI is entirely non-functional **[implemented]**
**Where:** `server.go` — the static file server is mounted **without** auth, while every
`/api/*` handler is behind `authMiddleware`. The SPA's `api()` helper sends no `Authorization`
header.

**Problem:** With `--password` set, the page loads fine (no challenge), then every data fetch
returns 401 and the UI silently shows nothing. Documented narrowly as "technique count silent" but
it is actually total breakage of the protected deployment mode.

**Fix:** Put the static handler behind a Basic-auth *challenge* (401 + `WWW-Authenticate`) so the
browser prompts once and then auto-attaches the credentials to all same-origin `/api/*` fetches.
No UI password field needed. Added a server test.

## Tier 2 — Correctness & consistency, addressed this pass

### 4. Non-deterministic ordering **[implemented]**
`Registry.GetTechniquesByPhase` and `GetAllTactics` iterate a Go map, so technique execution order
and the report's technique/tactic order change on every run. Sorted `GetTechniquesByPhase` by ID
and replaced two hand-rolled O(n²) bubble sorts with `sort.Slice`/`sort.Strings`. Runs and reports
are now reproducible.

### 5. Carried-forward tech debt **[implemented]**
- Tier not propagated on elevation-skip / WhatIf results → report shows em-dash. Now set.
- `runTechnique` WhatIf branch and `Start()` status init used `time.Now()` instead of the injected
  `e.clock` → breaks determinism guarantees. Now use `e.clock.Now()`.
- Dead code: `nextOccurrenceOfHour` is unused since the v1.4 window refactor. Removed.
- `go.mod`: all deps marked `// indirect` though several are direct imports. `go mod tidy`.
- `go vet` clean: two `net.Dial` "%s:%d does not work with IPv6" warnings in
  `native/t1046_scan.go` fixed with `net.JoinHostPort`. (`gofmt` is *not* clean
  repo-wide — struct-alignment predates gofmt discipline; left as-is to avoid a
  whole-repo reformat diff.)

### 6. Report/UI German remnants **[implemented]**
The HTML *report* (`reporter.go`) is still `lang="de"` with German column headers, badges, footer,
and the WhatIf strings in `engine.go` are German — inconsistent with the v1.1 English-UI decision
and confusing for the English-speaking consultant audience the report is shared with. Translated to
English (kept `reporter_test.go` in sync).

## Tier 3 — Recommended for a future milestone (not done here)

### 7. `DefaultQueryFn` swallows all query errors as "0 events"
A PowerShell/Get-WinEvent failure (bad channel, access denied) is indistinguishable from "event
genuinely absent" → reported as a verification *fail* rather than a *tooling* problem. Consultants
would benefit from a distinct `verify_error` status so they can tell "rule didn't fire" from
"couldn't query the log."

### 8. Verifier waits a fixed 3 s then queries once
Slow log pipelines (esp. forwarded/Sysmon) can write after the wait. A short bounded
*poll-with-backoff* (e.g. up to N seconds, re-query every second, stop when all found) would cut
false fails without inflating happy-path time.

### 9. Report is written to the process working directory
`reporter.SaveResults` writes `lognojutsu_report_*.{html,json}` and logs to CWD. On a client machine
launched from `C:\Windows\System32` (elevated) this scatters artifacts. Consider a dedicated
`--output-dir` (default next to the exe) and surface the resolved path in the UI.

### 10. No structured export for SIEM-side correlation
A machine-readable summary (already have JSON) keyed by MITRE technique_id + timestamp window +
expected events would let consultants diff against SIEM search results programmatically. Consider a
`--export csv|json` of the verification matrix.

### 11. `handleTechniques`/`handleCampaigns` return nondeterministic JSON arrays
Same map-iteration issue as #4 but on the API surface; sorting by ID gives the UI a stable list.
(Low priority — UI could sort client-side.)

### 12. Test coverage gaps
- `userstore` and `simlog` have no test files. DPAPI round-trip and store CRUD are untested.
- `T1070.001` missing from `TestWriteArtifactsHaveCleanup` (behavior correct, coverage gap).
- Race detector never run (`-race` needs CGO/gcc, absent on the dev box). A CI job on a
  gcc-equipped runner would validate the mutex discipline the code is careful about.

### 13. Sysmon download over the network at Preparation time
`InstallSysmon` fetches from `download.sysinternals.com`. The tool's selling point is "no internet
required." Consider embedding a pinned Sysmon config and documenting a manual Sysmon binary drop, or
gate the download behind an explicit flag.

### 14. AMSI detection is string-match heuristic
`isAMSIBlocked` matches English AMSI message substrings + one exit code. Non-English Windows or
message changes would miss. Low impact (best-effort signal) but worth a note.
